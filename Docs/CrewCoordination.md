# 船員間の作業予約と情報共有

## 背景と目的

味方AIが個別に最良の対象を選ぶと、同じ弾や砲台へ全員が集まる場合があります。対象ごとの担当を共有し、空いている別の作業を選ぶようにします。別の味方が見つけた弾や侵入者についても、期限付きの観測値を共有して移動先を判断します。

## 利用者の確認方法

1. `Assets/KadokaShipBattler/Scenes/BattlePrototype.unity`を開き、UnityのPlayを押してください。
2. Pキーで方針画面を開き、チームを`Bombard`にしてください。複数の味方が別の弾を担当し、運搬・装填・発射を進めます。
3. `Supply ammo`を補給役に、`Operate cannon`を砲手に設定してください。専門担当は通常担当より高い優先度で対象を引き継ぎます。
4. Tabで担当している船員を直接操作してください。その船員のAI予約を解放し、別のAIがその作業を選べる状態になります。
5. Rで戦闘を再開始してください。以前の予約と共有観測を破棄し、新しいチーム状態になります。

方針の能力条件は[チーム方針と個人方針](AiPolicies.md)を確認してください。直接操作する利用者の取得・砲台操作をAI予約で禁止することはありません。AIは次の観測と操作直前の確認で、取得済みの対象などを候補から除きます。

## 予約の手段

| 対象 | 予約の単位 | 解放する契機 |
|---|---|---|
| 弾 | 実在する弾のインスタンスID | 取得、到着時の再観測失敗、期限切れ、担当変更 |
| 砲台 | 砲台のインスタンスID。装填と発射で共通にします。 | 装填・発射の完了、担当変更、期限切れ |
| 自船内の侵入者 | 観測した敵船員のインスタンスID | 再観測失敗、死亡の観測、担当変更、期限切れ |

資源ごとに一人、船員ごとに一件の担当を保持します。別の船員が同等以上の優先度で担当している対象は、採点前に候補から除きます。空いている他の弾・作業があれば再評価し、候補がなければ待機して視野を回します。

予約の期限は2秒です。同じ担当の再評価で期限を更新します。更新がなくなれば回収します。同じ優先度での上書きを拒否するため、小さな点数変動で担当が行き来することを防ぎます。

| 優先度 | 条件 |
|---:|---|
| 0 | 通常担当です。 |
| 1 | 補給・特殊移動補給方針での運搬と装填、砲台操作方針での発射、警備方針での防衛です。 |
| 2 | 本人または味方が自船内の侵入者を観測した場合、または自船の船体残存率が25%未満の場合の防衛です。 |
| 3 | 専門の警備担当による緊急防衛です。 |

高優先度の担当へ引き継ぐと、旧担当の予約と逆引きを同時に解除します。予約には世代番号を付け、解放・再取得前の古い予約から操作することを拒否します。同じ担当の期限更新では世代を保持します。

死亡・行動不能・船員や実行器の無効化・直接操作切替で予約を回収します。経路失敗や移動速度0で目的地へ進めない場合も解放し、同じ船員はその対象の再取得を0.5秒避けます。戦闘終了・シーン終了では全ての予約を解除します。

## 共有情報の境界

チーム共有のブラックボードは、味方の報告をまとめて読む台帳です。登録した同じ戦闘のプレイヤー船員だけが報告します。AI担当に加え、直接操作中の味方も本人の視界を共有します。

共有するのは実際の`VisionSensor`が得たID・種類・陣営・位置・HP・弾の重量と威力・観測時刻です。対象のTransformや現在HPへの参照を持ちません。共有観測を別の船員の新しい本人観測として再報告することもありません。

観測の期限は元の観測から2秒です。古い値の再報告では期限を延長しません。報告者が対象を見失うと、その報告から対象を除きます。別の味方が引き続き観測していれば、その報告を使います。複数の報告では最新の観測を選び、同時刻なら小さい報告者IDを選びます。

死亡、センサーや船員の停止では、その報告者の情報を撤回します。取得や到着時の再観測失敗で無効と判断した対象は全報告から除きます。更新された本人の視界へ対象が再び入ると、新しい報告として共有します。

自船の部屋・ドア・砲台の位置と船体状態は既知情報として引き続き使います。共有台帳は未観測の敵の現在位置や状態を検索しません。共有位置から経路を求めますが、取得と攻撃には本人の現在の視界と操作直前の確認が必要になります。本人がまだ対象を見ていない段階では移動だけを行います。

現在の接続対象は弾・自船砲台・自船内の侵入者です。乗り込み先や重要地点の予約は、それらの行動の接続時に資源の種類を追加してください。敵の既存の定型AIには接続していません。敵のチーム戦術はIssue #11で接続します。

## 状態の所有者と性能

`TaskReservationBoard`は所有者と対象の逆引きを所有し、個別の取得・確認・解放を平均O(1)で行います。期限回収は予約数に比例します。`TaskTarget`は行動名から共通の資源キーを作り、`TaskReservation`は不変の担当値を保持します。

`SharedObservationBoard`は報告者ごとの観測と統合結果を所有します。観測は不変の値を参照し、更新用辞書と統合リストを再利用します。1報告は最大128対象に制限します。同じフレームの未変更状態を読む時は再統合しません。閲覧リストは次の統合で更新するため、永続的な履歴として保持しないでください。

`CrewTeamCoordinator`は戦闘と両台帳を接続し、報告と期限・行動不能時の回収を進めます。`CrewTaskAssignment`は船員の担当と経路失敗後の再取得時刻を所有します。`UtilityAiAgent`は他担当の候補を除外して予約し、`CrewAmmoAiController`は移動・操作直前に所有権を確認します。

## 検証範囲

`Tools/CI/Coordination/CoordinationChecks.csproj`は本番モデルをコンパイルし、競合・高優先度の引継ぎ・期限境界・失敗時の保持・不正入力・報告の所属と撤回を確認します。

PlayModeの`TaskReservationIntegrationTests`と`SharedPerceptionIntegrationTests`は実際のシーンを使います。別々の弾の担当、装填と発射の共有予約、旧担当の操作拒否、直接操作切替、死亡・停止・再開始、共有情報からの実際の補給と防衛を確認します。利用者の実際のキー入力や画面の見た目は、この自動シナリオの検証対象ではありません。
