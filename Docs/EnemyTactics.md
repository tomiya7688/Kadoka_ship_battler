# 敵チームの戦術ディレクター

## 背景と目的

敵の5人が、それぞれ別のスクリプトで動くと、全員が同じ弾へ集まる、砲手が弾を探している間に他の船員が立ち尽くす、橋が開いても一人しか乗り込まない、といった動きになります。敵5人が同じ目標を共有し、戦況に応じて目標と役割を変えるため、`EnemyTacticalDirector`（敵戦術ディレクター。以下ディレクター）を用意しました。

ディレクターは、敵船員の本人視界、自船の既知情報、公開される船体状態だけから判断します。プレイヤーの入力、視界外の船員の位置、プレイヤー船内の弾は読みません。

## 利用者の確認方法

1. `Assets/KadokaShipBattler/Scenes/BattlePrototype.unity`を開き、UnityのPlayを押してください。
2. F1キーでAIデバッグ表示を開き、`[Enemy]`の行で、敵チームの現在の共有目標を確認してください。開始直後は`Bombard`です。
3. プレイヤー船の船体HPが0になるまで、敵の砲撃を受けてください。橋が開くと、表示が`BoardEnemy`に変わり、敵の戦闘員が橋を渡ってプレイヤー船の部屋を順に捜索します。
4. 敵船の船体HPを0にして橋を開き、敵船の甲板へ二人以上の味方を進めてください。敵が侵入者を見ている間は、保持時間（2秒）を過ぎると`DefendShip`に変わり、敵の戦闘員が侵入者へ近づきます。

## 共有目標

| 目標 | 意味 | 成立する条件 |
|---|---|---|
| `Bombard` | 弾を運んで砲台へ装填し、砲撃する | プレイヤー船の船体が破壊されていない間 |
| `DefendShip` | 自船内の侵入者へ近づき、迎撃する | 常時（点数が0の場合もあります） |
| `BoardEnemy` | 開いた橋からプレイヤー船へ乗り込む | プレイヤー船の船体が破壊されている間 |

ディレクターは0.25秒ごとに、各目標を0以上1以下で採点します。最も高い目標を選びますが、次の条件があります。

- 現在の目標を2秒以上保持し、新しい目標が0.15以上高い場合だけ切り替えます。小さな点差で目標が行き来することを防ぐためです。
- 現在の目標が成立しなくなった場合（例: 橋が開いて`Bombard`が不可能になった場合）は、保持時間を待たず直ちに切り替えます。
- 生存している敵船員がいない間は、目標を保持します。

| 目標 | 点数の主な要素 |
|---|---|
| `Bombard` | 基本0.5。砲台に弾がある、または共有観測に自陣営の弾がある場合は+0.1。自船体の残存率が低いほど最大+0.3。プレイヤーの砲撃が速いほど最大+0.1 |
| `DefendShip` | 観測した侵入者1人につき0.4。自船体が破壊されている場合は+0.3。乗り込み傾向に応じて最大+0.3。上限は1 |
| `BoardEnemy` | 0.9から、観測した侵入者1人につき0.3を引きます。下限は0 |

## 役割

目標が決まると、`EnemyRoleAssigner`が生存している船員の能力から、一人に一つの役割を割り当てます。同じ入力からは常に同じ割り当てになります。

| 役割 | 実行する内容 |
|---|---|
| `Gunner`（砲手） | 弾を持つか砲台が装填済みなら砲台へ行き、装填し、10秒間隔を満たしたら発射します。弾がなければ、自分の視界にある弾を取りに行きます |
| `Supplier`（補給役） | 弾を拾って砲台へ装填します。自分で弾が見えない時は、味方が見つけた弾の位置へ移動します |
| `Defender`（迎撃役） | 観測済みの侵入者へ近づきます。攻撃は`CrewGuardAiController`が、自分の視界内の相手に対して行います |
| `Boarder`（乗り込み役） | 観測した核があればその位置へ、なければプレイヤー船の部屋を順に捜索します |

- 砲撃時: 戦闘・運搬・砲台操作をすべて持つ編成順で最も前の船員が砲手になります。運搬容量の大きい順に最大2人が補給役になります。残りの戦闘員は迎撃役です。
- 迎撃時: 戦闘員は迎撃役です。ただし、侵入者が1人の間は砲手が砲手のままです。補給役は戦闘をしない船員だけです。
- 乗り込み時: 戦闘と乗り込みの能力を持つ船員が乗り込み役です。侵入者を観測している場合は2人、プレイヤーの乗り込み傾向が0.5以上の場合は1人を、編成順で後ろの戦闘員から迎撃役として残します。

## 観測の共有

`EnemyTeamPerception`は、各敵船員の実際の`VisionSensor`が得た観測を`SharedObservationBoard`へ集めます。味方側と同じ台帳を使うため、観測の有効期限は2秒で、対象を見失うと報告から消えます。

共有された観測から、次の一覧を作ります。

- 侵入者: 自船の甲板上にいる、HPが0より大きいプレイヤー船員
- 自陣営の弾: 補給役への割り当てに使います
- プレイヤー陣営の弾: 傾向の推定に使います
- プレイヤーの核: 乗り込み役の移動先に使います

補給役が共有された弾の位置へ移動することは許可していますが、拾うには本人が現在その弾を見ている必要があります。到着しても見えない場合や、通行できない場合は、その報告を全員の共有から除きます。

乗り込み役の捜索地点は、プレイヤー船の部屋の中心です。船の間取りは両陣営が知っている情報として扱い、橋に近い部屋から順に回ります。核・船員・弾の位置は、実際に見るまで知らないものとして扱います。

## プレイヤーの傾向の推定

`PlayerTendencyEstimator`は、敵が実際に得た情報から次の値を推定します。

| 値 | 入力 | 戦術への影響 |
|---|---|---|
| 毎分の被弾数 | 自船体のHPが減った時刻（直近60秒、開始直後は10秒を最小窓にします） | 値が大きいほど`Bombard`の点数が上がります |
| 重い弾の割合 | 観測したプレイヤー陣営の弾の重量が3以上の割合。標本が3発に満たない間は0です | 割合が高いほど、自船体の危険度を大きく見積もります |
| 乗り込みの圧力 | 自船内で観測した侵入者数（2人以上で最大）。約10秒の時定数で減衰します | `DefendShip`の点数と、乗り込み時に残す迎撃役の数に影響します |

同じ弾を何度見ても、標本は1回だけ数えます。標本は最大256個、砲撃記録は最大32件です。

## 状態の所有者と性能

| 部品 | 所有する状態 | 依存 |
|---|---|---|
| `EnemyTacticalPlanner` | 現在の目標と切替時刻 | Unity非依存 |
| `PlayerTendencyEstimator` | 砲撃時刻、弾の標本、乗り込みの圧力 | Unity非依存 |
| `EnemyRoleAssigner` | なし（毎回の入力から割り当てを返します） | Unity非依存 |
| `EnemyTeamPerception` | 共有台帳と、種類別の観測一覧 | UnityのセンサーとShip |
| `EnemyTacticalDirector` | 判断の周期、砲撃間隔、弾の担当、捜索地点 | 上記すべて |
| `EnemyRoleController` | 経路探索の呼び出しと、拾得・装填・発射の実行 | NavigationAgent、VisionSensor |

判断は0.25秒ごとで、船員5人と共有観測数（1人最大128件）に比例します。移動と操作は毎フレーム進めます。判断のたびに、役割割り当て用の一時コレクションを作ります。

## 検証範囲

`Tools/CI/Tactics/TacticsChecks.csproj`は本番の戦術モデルをコンパイルし、次を確認します。

- 目標の選択、保持時間、点差、成立しない目標の即時切替
- 傾向の窓、標本の重複、減衰、時刻の逆行などの不正入力の拒否
- 役割割り当ての決定性、侵入者や乗り込み傾向による迎撃役の確保、ID重複の拒否

PlayModeの`EnemyTacticalDirectorTests`は実際のシーンを使い、橋が開いた時の乗り込み、侵入者を観測した時の迎撃、視野外の侵入者を無視すること、被弾の記録、共有された弾を補給役が取りに行き装填し砲手が発射するまでと、誰も弾を見ていない時に補給役が動かないことを確認します。

Unityエディターを使えない環境では、PlayModeテストの実行結果は得られません。画面の見た目、キー入力、実際の対戦の釣り合いは、この自動検証の対象外です。

## 既知の制限

- 敵の個別行動のうち、乗り込み役の戦闘は`CrewGuardAiController`の簡易な攻撃に依存します。
- 迎撃役が複数いる時の、侵入者の担当分けは行いません。全員が最も近い侵入者へ向かいます。
- F1キーのAIデバッグ表示は、エディターと開発ビルドだけで有効です。敵の個別の評価値は表示しません。
- 弾が飛ぶ処理と硬度判定はIssue #16で接続します。
